# Lumen roadmap

Target TV: LG 43UT91006LA, webOS 25 (Chromium 120), rooted, Homebrew Channel installed, Home button remapped with LG Input Hook.
Apps in daily use: PlxNative (Plex), youtube-webos, BBC iPlayer, Channel 4, Channel 5.

Each phase ends with a check on the TV before the next one starts. Items marked **(verify)** depend on something not yet tested on this TV.

---

## Phase 0: Safety net

Goal: the working install on the TV is never at risk while we change things.

- [ ] Keep a copy of the current `.ipk` (1.0.9) for rollback.
- [ ] Build the new version under a separate app id, `com.ammar027.lumen.dev`, with its own tile and its own settings, so it installs beside the working copy.
- [ ] Note the current Lumen settings (dock order, folders, wallpaper, options) so they can be recreated if needed.

Done when: a dev build and the current build both run on the TV side by side.

## Phase 1: A buildable app, plus small fixes

Goal: one command builds Lumen from this repo on any machine, and the known correctness and privacy issues are gone.

### Build
- [ ] Turn `app/` into a real fork: commit the launcher source into this repo, record the upstream commit it came from (partridgeworks/webos-launcher).
- [ ] Retire the `tools/apply_*.py` patch scripts once their changes are in the committed source. Delete the unused ones (`apply_clearer_glass.py`, `apply_motion.py`, `apply_launchfx.py`) and the `if True else` dead branch in `apply_tvos.py`.
- [ ] Remove hardcoded `~/Developer/webos-launcher-tvos` paths (`build_release.py`, `harvest.py`, `apply_tvos.py`). Use paths relative to the repo.
- [ ] Single build command, for example `npm run build:ipk`, that produces the `.ipk`.
- [ ] Build flavours: `dev` (`com.ammar027.lumen.dev`) and `stable` (`com.ammar027.lumen`). Dev is the default.
- [ ] Personal assets (third-party app logos, the private SF font) stay out of the public repo and out of public releases. Keep the logo-free release path that `build_release.py` already has.
- [ ] Keep `tools/screenshots.mjs` working as a visual check after each change.

### Deploy
- [ ] One-command deploy over `ssh` to the rooted TV for quick iteration (`.tv-host` file, gitignored, holds the address).
- [ ] Home-network Homebrew Channel repository: a static `apps.json` (same format as `https://repo.webosbrew.org/api/apps.json`) plus the `.ipk`, served from a machine on the LAN. Generated by the build (id, version, ipk URL, SHA-256, size).
- [ ] Add the repository on the TV once: launch `org.webosbrew.hbchannel` with `{"launchMode":"addRepository","url":"..."}`.
- [ ] **(verify)** The Homebrew Channel accepts a plain HTTP repository on the LAN. If not, serve it over HTTPS.

### Settings export and import
- [ ] Export the Lumen config to a file on the TV (`/var/lib/homehook/lumen-config.json`, via root) and import it on first launch or on demand. Needed because dev, stable and any reinstall each keep separate settings.

### On-TV error log
- [ ] Write failures from root commands, Luna calls and network requests to a log file readable over `ssh` (size-capped). Replaces silent failures and vague toasts.

### Correctness and privacy fixes
- [ ] `tools/tv/clockfix.sh`: stop forcing `Asia/Kolkata`. Use the TV's own time zone setting, or a variable at the top of the file.
- [ ] `clockfix.sh`: get the time over HTTPS, not from the `Date` header of plain HTTP requests.
- [ ] Weather location: make ipwho.is opt-in. Default to no city until one is chosen, or ask once.
- [ ] Remove the plain HTTP fallback for `sylvan.apple.com` videos, or make it a setting.
- [ ] `watch.sh`: only append `hosts-extra` lines that match `0.0.0.0 <hostname>` or `:: <hostname>`.
- [ ] Put every root shell command in one module with a fixed allowlist. Validate or shell-quote any value inserted into a command, even the ones that are safe today (picture mode, sound mode, screensaver minutes).

Done when: a fresh clone builds the `.ipk` with one command, it installs through the home-network repository, and the dev build behaves the same as 1.0.9 on the TV apart from the fixes above.

## Phase 2: Performance baseline and the blur test

Goal: know how fast Lumen is on this TV, so every later change can be checked against it.

### Measure
- [ ] Attach Chrome DevTools to Lumen on the TV and record traces.
- [ ] Record three numbers as the baseline:
  - Home press to home screen visible
  - Key press to focus moving (frame time while moving along the dock)
  - Cold start to interactive
- [ ] Add a frame-rate counter to dev builds only.

### Blur test
- [ ] Try real `backdrop-filter` on the dock only (not full screen, not Settings), behind a new setting: Graphics: Low (current pre-blurred glass) / High (live blur on the dock).
- [ ] Keep High only if the dock holds 60 fps while moving focus and while the video wallpaper plays. Otherwise drop it.

### Speed work
- [ ] Home resumes the running app instead of reloading it. Check the relaunch event is handled and that Lumen is not cold-starting on each Home press. **(verify)**
- [ ] Decode the next wallpaper or photo before swapping it in (`img.decode()` or `createImageBitmap`).
- [ ] Load Settings and Control Center only when first opened, so the home screen parses less JavaScript at start.
- [ ] `content-visibility: auto` on off-screen rows and panels.
- [ ] "Close background apps" button in Control Center (root, applicationManager close call) to free memory.
- [ ] Serve images at screen size or smaller. Video wallpaper at 720p rather than 1080p.

Done when: the three numbers are recorded before and after, and none of them got worse.

## Phase 3: UI tweaks

- [ ] Pop-up list picker for long options (weather city, country, language, picture mode, sound mode) instead of stepping through values with OK.
- [ ] Fix the focus label of the top-right button ("Control Center") showing through above the open Control Center panel.
- [ ] New settings:
  - [ ] Focus highlight strength
  - [ ] Tiles per dock row (5, 6, 7)
  - [ ] Hide app names under focused tiles
  - [ ] Video wallpaper only between set hours
  - [ ] Reduce motion (no animations)
- [ ] Control Center:
  - [ ] Sound output: TV speakers, soundbar (ARC or optical), Bluetooth
  - [ ] Backlight slider **(verify setting name on webOS 25)**
  - [ ] Eye Comfort toggle **(verify setting name on webOS 25)**
- [ ] Update the Settings descriptions that are out of date (video wallpaper text still says only Apple's aerials).

Done when: each new setting works on the TV and the Phase 2 numbers have not got worse.

## Phase 4: Colour buttons

- [ ] **(verify)** Which colour buttons the remote has. Some Magic Remotes only show them on the on-screen 123 pad.
- [ ] Settings > Remote: an action per colour button (red, green, yellow, blue). Actions:
  - Open a chosen app
  - Open Control Center
  - Screen off
  - Sleep timer (cycle)
  - Picture mode (cycle)
  - Sound output (cycle)
  - Start screensaver / ambient
  - Nothing
- [ ] These work while Lumen is in front (normal key events).
- [ ] Optional: LG Input Hook mappings so the buttons also work inside other apps, by calling Lumen with a launch parameter.

Done when: each button does its chosen action on the TV.

---

## Phase 5: Immich photos

- [ ] Settings > Photos: Immich server address and a read-only API key (`asset.read`, `album.read`, `memory.read`).
- [ ] Photos are fetched directly from the Immich server on the LAN. Never through images.weserv.nl or any other public proxy.
- [ ] **(verify)** Endpoint paths against the server's own `/api` docs (they have changed between Immich versions): albums, favourites, random, memories, thumbnail and preview sizes.
- [ ] Glass without live blur: fetch the small thumbnail, blur it once on an `OffscreenCanvas` in a worker, and use that as the glass backdrop. No per-frame cost.
- [ ] Step 1: Immich as a wallpaper source (chosen albums, favourites, shuffle, change every N minutes).
- [ ] Step 2: ambient screensaver that replaces LG's screensaver (same hook `watch.sh` uses for Lumen Gallery): full-screen photos, crossfades, slow zoom (opacity and transform only), clock and weather overlay, "On this day" memories.
- [ ] Prefetch and decode the next photo before it is shown.

Done when: photos load from Immich on the TV, the ambient screen runs for an hour without stutter or memory growth, and the Phase 2 numbers have not got worse.

## Later

In rough order of value:

1. Plex Continue Watching row from the Plex server's On Deck. Tiles open PlxNative. Opening a specific episode needs a launch parameter that PlxNative does not have yet (an upstream contribution).
2. Picture and sound mode per app (root; `watch.sh` already knows which app is in front).
3. YouTube subscriptions row (YouTube Data API, TV sign-in with a code), opening videos in youtube-webos with its `target` / `contentTarget` launch parameter.
4. Long-press shortcuts per app (for example YouTube: Subscriptions, Search).
5. Bedtime button: lower backlight, Eye Comfort and sleep timer together.
6. Recent-apps switcher on a spare remote button (LG Input Hook).
7. Auto-switch to an HDMI input when its device turns on; power off when idle.
8. Profiles, and a kids mode with a PIN and allowed hours.
9. Privacy page: LG ad and Live Plus settings, plus hosts-level blocking of LG ad and tracking hosts.
10. Live Freeview channel tiles **(verify the channel service on webOS 25)**.

## Parked

- Native (GPU) version of Lumen. Reference: PlxNative (Rust, SDL2, OpenGL ES 2, webosbrew native NDK; GPL-3, so read for approach only). If picked up again, start with a native Immich ambient screen as a pilot rather than the whole launcher.

## Not doing

- Live blur over large areas or full screen (too expensive on this GPU).
- Google Photos (since March 2025 third-party apps can only read photos they created or ones picked by hand).
- iPlayer, Channel 4 and Channel 5 content rows (no public APIs).
